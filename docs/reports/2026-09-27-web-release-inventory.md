The local `npm run build:web` stages the application and public media separately. It follows the referenced GLB models' external texture dependencies and excludes `.blend` source files, development study pages, tool directories, environment files and `node_modules`. It also excludes 29 local generated combat-audio candidates: the [audio authoring guide](../../tools/audio-gen/README.md) says their public distribution rights have not been cleared. The shipped combat matrix will use its existing bundled sound fallbacks until rights and listening review are complete. The generated application is under the conservative 200 MB package guard and the current Free-tier SWA cap; the media library is larger than that cap and needs its separate origin before the new 3D catalogue can be a complete production experience.

The working art, `data/combatScene.json`, local combat audio, and vendored Three.js files are currently untracked. The existing GitHub Actions checkout cannot reproduce this local build until approved runtime exports are made available to CI through a versioned source or a separate media publication workflow. At the initial inventory no media storage account or Front Door profile was found in the `nexus-verge` resource group.

One immutable copy of the current media set would occupy about 0.43 GiB in Blob storage; retaining three complete release prefixes would occupy about 1.29 GiB before redundancy and versioning overhead. As a traffic illustration, 1,000 players each downloading 25 MiB of distinct media in a month would transfer about 24.4 GiB through the media edge; 10,000 at the same rate would transfer about 244 GiB. These are assumptions, not observed usage or a complete bill. Front Door Standard currently has a US$35/month base fee before request and transfer charges; Blob capacity, transactions and cache misses add cost. Record actual audience geography and traffic before enabling the public route. [Azure Front Door pricing](https://azure.microsoft.com/en-us/pricing/details/frontdoor/)

The generated `dist/app` contains a media manifest and URL configuration. A production build should set `WEB_RELEASE_ID` and `WEB_MEDIA_ORIGIN`, publish `dist/media/releases/<release-id>/` with the manifest's MIME types first, verify real GETs and CORS, then deploy `dist/app`. The existing workflow still deploys the repository root, so these artifacts are staging evidence only.

Follow-up work for [#53](https://github.com/KnowledgeRatio/nexus-verge-crpg/issues/53) added a content-hash lock at `deployment/media-releases/combat-d9b7ff1f6eb7.json`. An app-only build can now consume that lock without local media binaries; the separate publisher verified all 107 local files and 438.52 MiB against their hashes in a dry run. A local HTTP preview returned 200 for the app and a model, 404 for a missing model and the omitted study page, and the media verifier checked all 107 paths, MIME, size and immutable cache headers. Browser gameplay and real Azure CORS/Front Door behaviour remain untested.

The clean-checkout guard currently finds 32 untracked app/config/lock files, including runtime rendering modules, vendored Three.js, `data/combatScene.json`, four player portraits, the release config and lock. The opt-in GitHub workflow can check and upload an app artifact after those sources are reviewed and committed; it does not deploy. On 2026-09-28 a separate Hot Standard LRS account, `nexusvergemedia`, and blob-read-only `media` container were provisioned from `deployment/media-storage.bicep`. The first upload attempt stopped before writing any blob because the signed-in user lacked a blob data role; a media-account-scoped Storage Blob Data Contributor assignment enabled the retry. All 107 locked assets (438.52 MiB) were then uploaded under `releases/combat-d9b7ff1f6eb7/`. The live HTTP verifier checked every HEAD response for size, MIME and immutable caching, a real missing-file 404, and the production SWA origin's CORS preflight. One anonymous full model GET returned HTTP 200 with 5,218,564 bytes; anonymous container listing returned HTTP 404. Anonymous visitors have read access to known blob URLs, without list or write permission. Front Door has not been provisioned, the assets have not been exercised in a browser, and production SWA remains unchanged.

The 2026-09-29 art audit found that `data/graphics/combat/` contains 166 local files. The 107-file media lock selects 75 GLBs and 32 PNG textures. Four more PNGs are player portraits used by character creation; their relative paths were initially missed by packaging and are now included in the app artifact, raising it to 172 files/63.02 MiB. The remaining 55 files comprise 44 editable `.blend` sources, nine GLB alternatives not referenced by the current combat configuration, one unselected texture and a README. `docs/art/` contains 324 study/documentation files and `tools/combat-art/` contains 203 source/authoring files; neither directory is loaded by the release app. These files may remain useful for editing, provenance or future art choices, but they are not all current runtime assets. No art was deleted in this audit.

`npm run lock:web-media` now reproduces this release lock from the selected local exports and refuses to overwrite a differing lock. A changed export produces a new content-hash prefix. On 2026-09-29 the approved 107 exports were archived in a separate private, versioned Blob account, and a branch-bound publishing identity was provisioned. The opt-in workflow still needs committed files and GitHub repository variables before a clean checkout can promote those private exports. The lock and public blobs preserve published releases; versioning and soft deletion protect the archived exports within the same account but do not independently back up editable source art.

Player loading time, GPU memory, audience geography and media traffic remain unmeasured. Those are release tuning inputs; they do not alter the chosen SWA + Blob/Front Door architecture.
