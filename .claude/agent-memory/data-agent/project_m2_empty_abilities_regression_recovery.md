**What happened:** The 19-monster `"abilities": []` fix logged in [[project_m2_attribute_batch_convert]] was never committed (standing no-auto-commit rule). A later agent ran `git checkout` on the uncommitted `data/monsters.json` to undo its own accidental reformatting, which silently reverted the whole file to last-commit state — discarding the ability-score fix too, since `git checkout` on a tracked file has no concept of "just my change." Redone from scratch in this session for all 19 (shadow, ghoul, specter, ghast, gargoyle, minotaur, wight, owlbear, flameskull, ettin, troll, wraith, hillGiant, the 3 young dragons, manticore, mage, medusa), plus their `abilitiesSixAttribute` siblings. Zero destructive git commands used this pass — every edit went through `Read`/`Edit` only, `git diff --stat` checked after as the reformatting tripwire (526 insertions/19 deletions for 19 monsters, proportional — no whole-file rewrite).

**Lesson for the team, not just this agent: an uncommitted fix is one careless `git checkout` away from silent loss, and it will not error — it will just quietly succeed and delete the other agent's work.** If asked to fix a subagent's own accidental full-file reformatting again, the safe move is a targeted `Edit`/diff-revert of only the reformatted hunks, never a blanket `git checkout` on a file with other pending uncommitted changes. This is a process risk independent of data-agent's own scope — worth surfacing to whichever role owns cross-agent workflow safety if it recurs.

**Derivation method used (repeatable for any future monster missing `abilities`):** `RULES.encounters.proficiencyByCR` (CR0–4: +2, CR5–8: +3, CR9–10: +4) is the actual runtime prof-bonus source for monsters (`EncounterBuilder.js`), not the level-based table. For a monster with an existing `savingThrows` or `skills` bonus, solve `abilityMod = givenBonus - profBonus[cr]` and pick the ability score giving that floor-mod, then fill unconstrained abilities with SRD-plausible values for the CR. A monster's `hitPoints` string (`"NdX+Y"`) encodes `conMod = Y/N` when it divides evenly — useful as a secondary CON check, but the plan's own precedent (Young Red Dragon) explicitly prioritizes matching `savingThrows`/`skills` over the HP-die bonus if they conflict; don't burn time reconciling both, saves win.

**Recurring pre-existing data quirk, not something to "fix": several monsters have two skills mapped to the same ability (e.g. wight's `perception`+`cunning` both WIS; young dragons' `perception`+`cunning` both WIS; medusa's `empathy`+`perception`+`cunning` all WIS) with bonus values that don't all resolve to the same ability-mod+prof under a single ability score.** Found in wight, youngWhiteDragon, youngRedDragon, medusa. Resolution used: pick the ability score that satisfies the majority / the skill matching real SRD values most closely, accept the other skill(s) as off by 1-4 — this mirrors how the original (lost) fix treated Young Red Dragon (reconciled against saves only, not every skill). Two of the three dragons' inflated `perception` numbers likely reflect the real 5e MM convention of dragons getting a "Keen Senses"-style doubled-proficiency Perception bonus that a flat ability score can't reproduce alone (confirmed clean for youngGreenDragon: WIS13 mod+1, `cunning`=4 matches mod+prof exactly, but `perception`=7 needs mod+prof+3 more — real SRD Young Green Dragon has this same non-formulaic Perception bonus). Not a bug to fix here — `skills`/`savingThrows` values were explicitly out of scope to touch (only `abilities` was to be populated) — just don't be surprised by it or attempt to "correct" the skill number to match a clean formula.

**AC is never derived from ability scores at runtime for monsters** — `EncounterBuilder.js`'s `createEnemyFromMonster` does `let ac = monster.armorClass` (flat passthrough), so DEX doesn't need to reverse-justify a monster's stated `armorClass`. Melee/ranged **attack bonus** for actions without an explicit `attackBonus` field *is* computed live from ability scores though (`CombatManager.calculateMonsterAttackStats` → STR for `meleeAttack`, DEX for `rangedFinesseAttack`/finesse/non-thrown-ranged) — so STR/DEX choices for monsters with raw (non-weaponId) attack actions do matter for actual combat balance, not just cosmetic consistency. Worth flagging to `balance-engineer` if any of these 19 monsters' fabricated STR/DEX ends up producing an outlier to-hit once played.
