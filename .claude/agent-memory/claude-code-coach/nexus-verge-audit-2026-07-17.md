Full audit performed 2026-07-17 of Nexus Verge's `.claude/` setup (CLAUDE.md + 5 always-loaded rule files, 12 mirrored skill/subagent pairs, 8 populated agent-memory dirs, path-scoped `.claude/rules/systems/*.md` + `ui.md`). Findings below are open items to re-check on the next audit rather than settled facts — verify current state before citing.

**Memory staleness (highest-leverage finding):** every populated `agent-memory/<role>/` file was last written 2026-07-01 (the same day as the mirroring decision record) — all in one batch. As of 2026-07-17 (16 days, multiple active sessions per CLAUDE.md's "Current State" block), zero new memory entries in any role except an empty `balance-engineer/` dir created same-day as this audit. The memory content itself is genuinely good (specific, non-obvious, load-bearing — e.g. architect's ADR-011 Effect Schema notes) but looks like a one-time backfill, not an actively-maintained system. **Why it matters:** if true, recent sessions aren't invoking the subagent form in a way that triggers memory writes (or are invoking it without the memory-update instruction landing) — the investment isn't compounding. **How to apply:** ask the user directly whether recent work has gone through subagents at all, or mostly through skill-persona/main-thread mode, before recommending further memory investment.

**legal-reviewer subagent never told to update memory:** `.claude/agents/legal-reviewer.md` has `memory: project` in frontmatter but is the only one of 12 agent files with no "Update your agent memory with..." closing instruction (verified via grep, 2026-07-17). Its memory dir has one file (2026-07-01, 35 lines) that will likely never grow. Easy fix: add the same closing instruction pattern the other 11 roles have.

**4 roles with zero subagent-memory footprint ever:** `creative-prompt-engineer`, `data-agent`, `mechanics-master`, `refactor-engineer` have no `agent-memory/` dir at all as of 2026-07-17, despite ~7 months of active project history and all four having `memory: project` + "update your memory" instructions wired correctly. This is circumstantial evidence (not proof) that these roles' **subagent form specifically** may rarely or never be invoked — work may be happening entirely through their skill-persona form instead, where the isolation/tool-restriction rationale for having a subagent at all doesn't get exercised. Worth asking the user directly next time: has each of these 4 ever actually been delegated to as a subagent (not just used as a skill)? If not, that's the concrete evidence needed to consider pruning those 4 back to skill-only. See [[skill-subagent-mirroring-tradeoff]].

**docs/ARCHITECTURE.md stale references:** `docs/ARCHITECTURE.md` was retired 2026-07-01 to a 6-line stub pointing at `.claude/rules/architecture.md`. `CLAUDE.md:10`, `.claude/agents/devils-advocate.md:18`, `.claude/agents/mechanics-master.md:20`, `.claude/agents/backend-dev.md:76`, `.claude/skills/architect/SKILL.md:31`, `.claude/skills/devils-advocate/SKILL.md:23`, `.claude/skills/game-designer/SKILL.md:51` still point agents/skills at `docs/ARCHITECTURE.md` as if it holds real content. Only `architect.md` itself has the retirement caveat. CLAUDE.md's own "In progress: rules directory migration + restyle" note confirms this migration is self-acknowledged as incomplete — this is the concrete leftover.

**backend-dev/MEMORY.md near the 200-line auto-memory cap:** 191/200 lines as of 2026-07-01 snapshot. Next substantial addition risks tripping the curation-required threshold. Worth checking if it's been split into topic files since.

**worldbuilder agent-memory holds work-product, not just institutional knowledge:** `dialogue_draft_{culture}.json` files (17-35KB each) live in `agent-memory/worldbuilder/` alongside genuine memory files (tone rulings, canon decisions). These read as actual content drafts, not "lessons learned" — worth flagging if this recurs, since it blurs memory (durable conventions) with deliverables (should probably live in `data/` or `docs/drafts/`).

**Global skills sync verified clean:** all 12 `.claude/skills/*/SKILL.md` files matched byte-for-byte against `~/.claude/skills/*/SKILL.md` as of 2026-07-17 — the manual-sync workflow rule is actually being honored, not drifting. Good practice to name explicitly if re-auditing.

**Redundant @-imports possible:** CLAUDE.md explicitly `@`-imports the 5 always-loaded rule files, but per current docs, `.claude/rules/*.md` files without `paths:` frontmatter auto-load at launch regardless of any `@`-import. The 5 always-loaded files (workflow.md, architecture.md, code-style.md, data-integrity.md, d5e-compliance.md) have no `paths:` frontmatter, so the explicit `@`-imports in CLAUDE.md are likely redundant with automatic directory discovery. Not confirmed as literal double-loading (didn't verify via a live `/context` check) — flagged as worth the user running `/context` once to confirm, then simplifying CLAUDE.md by dropping the @-import lines if redundant.
