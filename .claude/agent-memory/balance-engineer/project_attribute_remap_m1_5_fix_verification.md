Follow-up to [[project_attribute_remap_m1_postimpl_findings]]. All three bugs found there are confirmed FIXED against the real, current code (`getBlendedAttributeModifier` in `src/utils/attributeResolver.js` now divides by `entry.attributes.length`; `Character.js`'s `calculateAbilities()` and `EncounterBuilder.js`'s `createEnemyFromMonster()` both call the new shared `src/utils/attributeConversion.js`'s `convertLegacyAbilitiesToSixAttribute()` in `'sixAttribute'` mode; `EffectDispatcher.js`'s `rollDefenderSave()` now checks `defender.character.savingThrows[attr]` before falling through to the ability-modifier default). 21/21 automated checks pass (Sections A/D/E deterministic, B/C Monte Carlo + deterministic DC table).

**Point 1 — Menacing Attack DC deltas:** PureProwess matches the approved table exactly: **-2/-3/-3/-3 at L3/5/7/10**. Balanced does NOT match the plan's literally-quoted -1/-1/0/-1 — real numbers are **0/0/0/-1**. This is not a code bug: the plan's Balanced column was stale, carried over from the pre-fix double-floor formula (`floor(Prowess_mod/2)+floor(Presence_mod/2)`) and never re-verified when the PureProwess column was corrected to sum-raw-floor-once (per `project_menacing_attack_full_convergence.md`'s Q4 finding). With the Balanced build used throughout this line of harnesses (Prowess==Presence at L3/L5/L7 by construction, e.g. 16/16, 17/17, 18/18), the LOCKED formula (`floor((Prowess_mod+Presence_mod)/2)`) is mathematically forced to produce delta 0 whenever the two blended stats are exactly equal — averaging two identical values changes nothing. Only L10 (where ASI investment diverges the two stats by one point, 20/19) produces a real -1. **Plan doc corrected in place** (`docs/plans/2026-07-30-attribute-system-remap.md`, decision #5, "Correction —" paragraph added 2026-08-01) rather than left stale, per workflow.md's "update on contact" rule. Net effect: Balanced players pay *less* DC tax than documented, not more — favorable direction, no player-facing regression.

**Point 2 — Flee dump-punishment shape/magnitude:** intact and now correctly scaled (not doubled). Deterministic modifier table (no RNG): Balanced is exactly **+1 flee modifier over both dump builds at every level tested (L1/5/10)** — PureProwessDump and PureInsightDump converge to identical values at each level (mathematically necessary: flee is `floor((Prowess_mod+Insight_mod)/2)`, a symmetric average, so swapping which stat is dumped doesn't change the result). This is a modest, consistent, real cost — not the 2x-inflated pre-fix magnitude, not a trivializing bonus either. Monte Carlo (600 trials/cell) confirms the direction but several cells aren't statistically distinguishable at this trial count (probabilities saturate in the 50-70% band where a ±1 modifier shift produces a smaller win-rate delta than at the extremes) — the deterministic modifier table is the load-bearing proof here, Monte Carlo is directional confirmation only.

**Point 3 — Save-override wiring (Bug 3):** confirmed working with real `data/monsters.json` zombie/mage data. Zombie: hand-authored `savingThrows.wis:0` → override applied is `0`, vs. what the flat ability-modifier default would have given (`-2`, from real WIS 6). Mage: hand-authored `savingThrows.wis:4` (cha absent, so unaveraged passthrough per `averageComposureSaveBonus`) → override applied is `4`, vs. ability-mod default `1` (from real WIS 12/CHA 11 averaged). Both real, clearly-distinguishable deltas, extracted deterministically via a `Math.random` stub (forces `rollD20()` to always return 1, isolating the applied modifier exactly) rather than inferred from noisy Monte Carlo — confirms the override path is live, not falling through to the default.

**Point 4 — other regressions:** none found. Player-character save shape (`{proficient, bonus}` object, not a plain number) correctly falls through the `typeof === 'number'` guard in `rollDefenderSave()` and is unaffected by the override path.

**Verdict for the M1.5 flip-readiness gate:** all three previously-blocking bugs are fixed and verified against real code, not just read. The one discrepancy found (Balanced Menacing DC column) is a stale documentation number, not an implementation defect, and has been corrected in the plan file itself. Recommend to Chief Designer: clear to consider M1.5 flip-ready on the attribute-formula correctness axis. Does not re-litigate scope still flagged elsewhere in the plan as unbuilt (chargen remap, Scholar/Wanderlust, 46-monster batch convert) — those remain open M2/future items, unrelated to this fix-verification pass.

**Harness:** `tools/balance-sim/attribute-remap-post-fix-verification-sim.js` — supersedes the pre-fix `attribute-remap-post-implementation-sim.js` (kept for historical record of the original bug-finding trace, not deleted). 600 trials/cell for Monte Carlo sections (matches all four prior passes in this directory); deterministic sections (A/D/C-DC-table/E) need no trial count — same input always produces the same output, appropriate given [[feedback_simulating_unimplemented_systems]]'s general principle of using the real code path rather than statistical inference wherever a direct computation is available.
